For each actual exercise, create a new uniquely named folder and record:

| Field | Record |
|---|---|
| Exercise and actual timestamp | Which request was run and when |
| Skill(s) and library version | What was loaded; use a verified commit or note unknown |
| Inputs | Exact source files, versions and any user decision responses |
| Output | Actual artifact paths or observed blocker |
| Expected behavior | A specific source-grounded check, not an assumed result |
| Observation | What the assistant actually did, with output locators |
| Status | Not run, observed satisfactory, issue found, blocked or inconclusive |
| Follow-up | Reproduction prompt and proposed improvement, if evidenced |

Check provenance, unknown-rule handling, business-vs-engineering scope, connected behavior, artifact destination, permission boundaries and honesty of status claims. A satisfactory trial is bounded evidence, not proof that the skill always works.

Keep skill improvement proposals here until a separate request authorizes editing the reusable library. Do not append fictional test runs or stakeholder approvals to make an evaluation look complete.
